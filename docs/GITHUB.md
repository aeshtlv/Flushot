# Публикация

Репозиторий: **https://github.com/aeshtlv/Flushot**. Страница программы: **https://flushot.ink**
(свой сервер, см. [HOSTING.md](HOSTING.md)).

## Что лежит в репозитории

Исходники, документация и кадры интерфейса. Всё тяжёлое исключено через `.gitignore`:

| Исключено | Причина |
|---|---|
| `node_modules/` | восстанавливается командой `npm install` |
| `out/`, `release/` | результат сборки |
| `share/*.zip` | 94–143 МБ на файл: три архива раздули бы репозиторий до 330 МБ, а каждый коммит хранил бы их копию |
| `.tmp/`, `.cache/`, `.npm-cache/` | рабочие каталоги |

Архивы с программой живут в **Releases**: там лимит на файл 2 ГБ, и они не попадают в историю git.
`README.md` и кнопки на сайте указывают на `releases/latest/download/...`, поэтому после публикации
релиза ссылки работают сами.

## Выпуск новой версии

1. Поднять `version` в `package.json` — она должна совпадать с тегом релиза, иначе имя файла
   в ссылке разойдётся с прикреплённым архивом и кнопка «Скачать» отдаст 404.
2. Собрать и упаковать: `npm run dist`, затем разложить архивы в `share/` — см.
   [DEVELOPMENT.md](DEVELOPMENT.md#сборка-и-упаковка).
3. Создать релиз с тегом `v<версия>` и прикрепить пять файлов:

   - `Flushot-<версия>-x64.exe` — установщик
   - `Flushot-<версия>-x64.exe.blockmap`
   - `latest.yml`
   - `Flushot-<версия>-win64.zip`
   - `Flushot-<версия>-portable.zip`

   Первые три — **россыпью, не в архиве**. `electron-updater` строит адрес обновления из имени
   файла внутри `latest.yml` и `share/Flushot-<версия>-installer.zip` не откроет: он скачивает
   то, что написано в `latest.yml`, и вложенный архив для него не существует. Релиз должен быть
   опубликован (не черновик): `releaseType: release` ведёт обновление в `/releases/latest`,
   а черновик туда не попадает.

Через веб-интерфейс: **Releases → Draft a new release**. Через GitHub CLI — версию
берём из `package.json`, чтобы команда не разошлась с тем, что собрано:

```bash
V=$(node -p "require('./package.json').version")
gh release create "v$V" --title "Flushot $V" --notes-file CHANGELOG.md \
  "release/Flushot-$V-x64.exe" "release/Flushot-$V-x64.exe.blockmap" "release/latest.yml" \
  "share/Flushot-$V-win64.zip" "share/Flushot-$V-portable.zip"
```

4. Обновить `CHANGELOG.md` и имена архивов в `README.md` и `README.en.md`, затем прогнать
   `npm run verify:docs`. Страница на сайте правится в ветке `site`: там же и её проверки.
5. Посчитать скачивания — **не обязательно вручную**: `npm run stats` делает это сразу, а дальше
   числа обновляются сами (см. «Счётчик скачиваний» ниже). Скрипт читает `download_count` у файлов
   последнего релиза, пишет строку в README между маркерами и падает, если в релизе нет установщика,
   `latest.yml` или `.blockmap` — то есть если автообновление у только что выпущенной версии
   работать не будет.

## Счётчик скачиваний

Число «сколько раз скачали» есть только у GitHub: он считает обращения к файлам релиза сам, а
программа не отправляет ничего. Копируют это число в три места два разных механизма.

**Каждый день** запускается `.github/workflows/stats.yml` (03:17 UTC или вручную через
«Run workflow»). Он берёт `download_count`, пишет новое число в оба README и на страницу в ветке
`site`, пересобирает английскую страницу из русской, проверяет, что оба языка показывают одно и
то же, и коммитит в обе ветки. Если число не изменилось — не коммитит ничего.

Тот же запуск выкладывает страницу на GitHub Pages — зеркало `aeshtlv.github.io/Flushot`. Без
этого шага зеркало отстаёт: **пуш, сделанный встроенным `GITHUB_TOKEN`, не запускает другие
воркфлоу** (так GitHub защищается от зацикливания), поэтому `Pages` не срабатывает на коммиты
бота и зеркало показывает прошлое число. Это было замечено на живом примере: на
`flushot.ink` стояло 45, на зеркале — 44.

**Каждые 30 минут** на сервере срабатывает cron и запускает `/root/refresh-site.sh`. Скрипт
сравнивает голову ветки `site` с тем, что выложено сейчас (`/var/lib/flushot-last-deployed`), и
вызывает `deploy-site.sh` только если они разошлись. Журнал — `/var/log/flushot-refresh.log`:
в нём только настоящие выкладки и ошибки, тишина означает «ничего нового».

Между этими двумя шагами проходит до получаса, так что `flushot.ink` может отставать от GitHub
на час. GitHub в это время показывает верное число сам.

Счётчик считает и служебные файлы обновления — `latest.yml` и `.blockmap` — **не** считает:
установленная копия читает их при каждой проверке, и тогда число показывало бы машины, а не людей.
Посмотреть сырые числа по каждому файлу: `node scripts/download-count.cjs` без аргументов.

Если воркфлоу отключён (Settings → Actions → «Download counter» → Disable), ничего не сломается:
числа просто перестанут обновляться, и их можно поправить командой `npm run stats` + `--site`.

## Чего нельзя делать с релизом

**Не перезаписывать файлы в уже опубликованном релизе.** GitHub считает каждый ассет отдельно:
удаление и загрузка заново обнуляют его `download_count`, и счётчик «сколько раз скачали» навсегда
теряет всё, что было. Заодно у тех, кто уже обновился, `latest.yml` с прежним номером версии
перестаёт совпадать с содержимым, и обновление молча не приходит.

Поэтому исправление — это **новый номер версии**, а не новая сборка под старым тегом.

## Ветки

В репозитории две долгоживущие ветки, и они не сливаются:

| Ветка | Содержимое |
|---|---|
| `main` | программа: `src/`, `tests/`, `build/`, `scripts/`, `docs/` |
| `site` | лендинг: `site/`, `smm/`, `source/`, `logo/` и свои скрипты |

Страницы в `main` нет намеренно: репозиторий программы должен читаться как программа. Слияние
`main` в `site` вернуло бы `site/` и `smm/` обратно, поэтому ветки независимы, а общие файлы
(`logo/logo.svg` и шесть снимков интерфейса) лежат в `site` копиями. Как обновлять снимки —
в README самой ветки.

## Сайт

Боевой сайт живёт на своём сервере: **https://flushot.ink**, nginx, выкладка командой
`bash /root/deploy-site.sh`. Она забирает ветку `site` по закреплённому SHA коммита. Как это устроено — в
[HOSTING.md](HOSTING.md).

GitHub Pages остаётся как резервная копия. Workflow `.github/workflows/pages.yml` в ветке
`site` выкладывает папку при каждом изменении в ней; источник уже настроен:
**Settings → Pages → Build and deployment → Source: GitHub Actions**. Копия доступна по адресу
`https://aeshtlv.github.io/Flushot/`, но в её `canonical` указан `flushot.ink`, поэтому
поисковики не считают её дублем.

Проверки страницы запускаются в ветке `site`:

```bash
npm run verify      # ссылки, контраст, разметка, шрифты, адреса архивов
npm run shots       # рендер в headless-браузере на шести ширинах
```

При переезде на другой домен нужно обновить `canonical`, `og:url`, `og:image` и `twitter:image`
в начале `site/index.html`, а также `sitemap.xml` и `robots.txt` — им нужен абсолютный адрес.
## Что проверить после публикации

- Главная страница репозитория показывает `README.md` с картинками из `docs/` и `logo/`.
- Вкладка **Releases** содержит установщик, `latest.yml`, `.blockmap` и два архива, и ссылки
  из README открываются.
- Автообновление проверено на предыдущей версии: `Flushot.exe --update-check` на установленной
  копии печатает `ready` с номером новой версии, а не `current` и не ошибку.
- Вкладка **Actions** — зелёные прогоны `CI` (типы, тесты, документация) в `main` и `Pages`
  в ветке `site`.
- Сайт открывается по адресу `https://flushot.ink`, кнопки на нём скачивают архивы. Копия на
  `https://aeshtlv.github.io/Flushot/` остаётся рабочей, но её `canonical` указывает на свой
  домен: поисковики считают основной версией `flushot.ink`.
- В файловом дереве нет ни одного файла больше 100 МБ.

## Чего в репозитории намеренно нет

- **Готовых exe.** Они в Releases: в git они попали бы в историю навсегда, и каждый выпуск утраивал бы
  размер клона. По той же причине `latest.yml` и `.blockmap` лежат только в релизе — их собирает
  `electron-builder` на каждый выпуск.
- **Снимков рабочего стола.** Все кадры в `docs/` отрисованы в настоящей сборке интерфейса.
- **Сертификата подписи.** Сборки не подписаны, поэтому SmartScreen предупреждает. Для распространения
  нужен сертификат code signing и настройка `win.signingHashAlgorithms` в `electron-builder.yml`.
