# Разработка

Требования, команды, самопроверка, упаковка и проверки. Всё проверено на Windows 10/11 x64.

Пользовательская часть — в [README](../README.md), устройство — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Требования: **Windows 10/11 x64**, **Node.js 20.19+ или 22.12+**, npm.

```bash
npm install          # зависимости (sharp ставится как предсобранный бинарник)
npm run dev          # запуск с горячей перезагрузкой
```

Иконки в `build/` уже лежат в репозитории, поэтому для запуска и сборки ничего дополнительно генерировать не нужно. Перерисовать их из `logo/logo.svg` (после замены логотипа) — `npm run icons`.

При первом запуске открывается окно настроек, приложение остаётся в трее. Свернуть окно можно — горячая клавиша работает всегда, даже когда окно закрыто.

Полезные команды:

```bash
npm run typecheck    # tsc для main + renderer
npm test             # Vitest: 351 тест в 23 файлах
npm run build        # production-сборка в out/
npm start            # запуск собранной версии
npm run self-test    # сквозная проверка: захват, рамка, PNG/JPEG/WebP, пометки, буфер, UI
npm run dist         # установщик + portable в release/
```

Эти же `typecheck` и `test` прогоняет CI на каждый push и pull request (`.github/workflows/ci.yml`, Windows).

### Самопроверка

`npm run self-test` запускает приложение без пользователя и печатает JSON-отчёт:

```json
{
  "ok": true,
  "displays": [{ "label": "MSI G255F", "scaleFactor": 1, "image": { "width": 1920, "height": 1080 } }],
  "canvas": { "width": 2048, "height": 1208, "expectedWidth": 2048, "expectedHeight": 1208, "frame": 64 },
  "perf": { "composeMs": 109, "stitchMs": 27, "overlayMs": 237, "cardKB": 176, "card": "1628 × 1328", "ok": true, "note": "" },
  "hotkeyRebind": { "ok": true, "requested": "CommandOrControl+Alt+9", "saved": "CommandOrControl+Alt+9", "registered": true },
  "previewResize": { "ok": true, "narrow": "470px frame / 480px image", "wide": "850px frame / 848px image" },
  "accelerators": { "ok": true, "checked": 34, "rejected": [] },
  "ocr": { "ok": true, "supported": true, "lines": 1, "ms": 268, "text": "Flushot self test" },
  "fullscreen": { "ok": true, "size": "2048×1208", "selected": "1920pxx1080px", "shortcut": "CommandOrControl+Shift+3" },
  "clipboard": "image/png",
  "errors": []
}
```

Поле `perf` — это измеренная скорость, а не оценка: время сборки карточки, время склейки мониторов, время до появления окна выделения и размер готового файла. Если любое из значений выходит за предел (300 / 80 / 600 мс), `perf.ok` становится `false`, причина пишется в `perf.note`, а весь отчёт получает `ok: false`.

`hotkeyRebind` — это не проверка наличия кода, а живой цикл: сочетание сохраняется через тот же IPC-вызов, что и из окна, затем проверяется `globalShortcut.isRegistered`. `previewResize` измеряет рамку превью и натуральную ширину картинки до и после растягивания окна с 520 до 900 px — так ловится именно тот баг, когда превью остаётся на месте, а рядом появляется пустота.

`ocr` — распознавание против настоящего движка Windows: самопроверка рисует картинку с известной надписью, прогоняет её через тот же путь, что и кнопка «Текст», и требует, чтобы в ответе было это слово. Путь настоящий, то есть с запуском всех движков и склейкой, поэтому проверка ловит и поломку свода, а не только отсутствие движка. Картинка берётся из `src/main/ocr/sample.ts`, и тот же образец проверяет модульный тест — иначе `--self-test` мог бы упасть по причине, не связанной с приложением. Если движка в системе нет, проверка не валит отчёт: `supported: false`, `ok: true`, и в `note` написано, почему.

Отчёт, готовые PNG/JPEG и скриншоты обоих окон сохраняются в `%TEMP%\flushot-self-test\`. В оверлее есть демо-режим (`out/renderer/overlay/index.html?demo=1`), который рисует синтетический рабочий стол без захвата экрана — им пользуется самопроверка.

## Сборка и упаковка

```bash
npm run build        # только production-бандлы в out/
npm run dist         # NSIS-установщик + portable в release/
npm run dist:dir     # распакованная сборка release/win-unpacked для отладки
```

Результат в `release/` (номера версий подставляет `electron-builder` из `package.json`):

| Файл | Назначение |
|---|---|
| `Flushot-<версия>-x64.exe` | установщик NSIS (выбор папки, ярлыки, деинсталлятор) |
| `Flushot-<версия>-portable.exe` | portable-версия без установки |
| `win-unpacked/` | распакованное приложение (создаётся `npm run dist:dir`) |

Для передачи архивы раскладываются в **`share/`**: `Flushot-<версия>-win64.zip` (вся папка `win-unpacked` плюс инструкция `ПРОЧТИ МЕНЯ.txt`), `Flushot-<версия>-installer.zip` (внутри только установщик), `Flushot-<версия>-portable.zip` (внутри только portable). Внутри нет вложенных папок и служебных файлов. Архивы в репозиторий не попадают — они весят по 110–160 МБ; для них есть GitHub Releases, см. [GITHUB.md](GITHUB.md).

Конфигурация — `electron-builder.yml`. Иконки лежат в `build/`: `icon.png` для окна и `icon.ico` для установщика, обе собираются из `logo/logo.svg` командой `npm run icons` и лежат в репозитории, чтобы `npm run dist` работал сразу после клонирования. `asarUnpack` обязателен: нативные бинарники `sharp`/`@img` не могут исполняться из asar.

## Сайт, кадры и проверки

Лендинг в `site/` — статический, без сборщика. Скрипты:

```bash
node scripts/build-site.cjs              # картинки, значки, превью ссылки
node scripts/serve-site.cjs              # локальный сервер для предпросмотра
node scripts/verify-site.cjs             # проверки страницы без браузера
```

Кнопки скачивания на странице ведут в GitHub Releases, а не на файлы рядом с `index.html`. Поэтому `site/` публикуется как есть — ни архивов, ни сборки внутри не нужно, — а `verify-site.cjs` сверяет адреса с `package.json` (тот ли репозиторий) и с именами файлов в `share/` (есть ли такой архив). Архивы в репозиторий не попадают: они весят по 110–160 МБ.

- `verify-site.cjs` — все ссылки ведут на существующие файлы, кнопки скачивания указывают на этот репозиторий и на существующие имена архивов, у картинок верные размеры и alt, контраст не ниже WCAG AA в обеих темах, нет дубликатов `id` и незакрытых тегов, нет внешних шрифтов и трекеров, превью ровно 1200×630.
- `shot-site.cjs` — рендер в headless-браузере на пяти ширинах (320, 390, 820, 1180, 1440): горизонтальной прокрутки нет, ничего не обрезано, меню открывается, контраст проверяется по отрисованному результату, а не по стилям.
- `test-hotkey-demo.cjs` — 18 проверок демонстрации клавиш: запись сочетания, одиночная клавиша, конфликт двух полей, отказ `Esc`, возврат по `Backspace`, отмена по `Esc`, контраст строки состояния в обеих темах.
- `verify-demo-scene.cjs` — геометрия сцены: все 47 текстовых элементов внутри окна, ничего не наложено и не вылезает за колонку.
- `verify-ui-shots.cjs` — 45 проверок кадров интерфейса: выделение и его размер, восемь маркеров, подпись размера в физических пикселях, обе панели инструментов, две пометки на карточке, толщина подчёркивания и диагональ стрелки, напечатанные на кнопках сочетания и строка под карточкой, которая называет действия словами, кнопка распознавания, обводка фрагмента с отправкой именно вырезанного прямоугольника и нажатие без обводки, читающее весь снимок, панель текста внутри слоя результата и в пределах одного монитора, редактор распознанного текста, логотип в заголовке настроек (это `<svg>` с тёмным квадратом `#111111`, скруглением 44 и десятью элементами цвета `#A3C8F0`, выровненный по слову «Flushot»), размеры окна настроек и то, что в строке горячей клавиши остались только поле и «Сброс», размеры двух мониторов, то, что окно гаснет **до** команды скрыть, и — отдельно — что при копировании в приложение уходит **сырой блок только с краской**, а не весь холст.
- `make-ui-shots.cjs` — снимает кадры интерфейса для сайта. Он не берёт снимок вашего рабочего стола: поднимает локальный сервер, открывает в headless-браузере **настоящую сборку окна выделения** и подменяет только `window.flushot` — прослойку к Electron. Дальше работают штатные компоненты: затемнение, рамка выделения, маркеры, панели, холст пометок. Карточку результата собирает тот же `composeScreenshot`, что и в приложении, поэтому рамка, тень и скругление на картинке — те же. Подложка — синтетическая сцена из `demoScene.ts`. Никаких снимков чужого или вашего экрана в репозитории нет.
- `shot-marketing.cjs` — пересобирает картинки в `site/screenshots/` из живой страницы: десктоп в обеих темах, телефон, отдельные разделы.
- `make-og-image.cjs` — рисует превью ссылки 1200×630 в браузере теми же шрифтами и цветами, что и страница.
- `make-promo-images.cjs` — картинки для `smm/`. Скрипт сам проверяет, что каждый текстовый блок отрисовался, не вылез за отведённое место, не наехал на макет окна и что между блоками нет дыр и наложений; при нарушении он падает с перечнем проблем, а не отдаёт кривую картинку.
- `make-hero-image.cjs` — первый экран сайта: синтетическая сцена прогоняется через тот же `composeScreenshot`, что и ваша область, поэтому рамка, тень и скругление на картинке — те же, что вы получите.
- `make-tray-sheet.cjs` — перерисовывает `docs/tray.png`: обе раскраски значка в трее на светлой и тёмной панели задач, в четырёх размерах, с увеличением в 6 раз без сглаживания (чтобы видеть настоящие пиксели).
- `generate-icons.mjs` — `build/icon.png`, `build/icon.ico` (шесть кадров), `build/tray.png`, `build/tray-dark.png` из `logo/logo.svg`.
- `build-fonts.cjs` — вшивает Inter и JetBrains Mono в `site/fonts.css` как `data:`-URL.

Шрифты лежат прямо в `site/fonts.css` в виде `data:`-URL, а не отдельными файлами. Причина не в экономии: Chromium запрещает загружать шрифт по `file://` как кросс-доменный запрос, поэтому при открытии страницы двойным кликом подключённый файл молча не применяется и текст рисуется системным шрифтом. На машине, где Inter установлен, это незаметно — то есть проверка «у меня выглядит нормально» здесь ничего не доказывает.

Найденные этими проверками дефекты уже исправлены: кнопка «Скачать» в шапке была серой на синем (1,22:1) из-за более специфичного правила меню, а ответы в FAQ шли по 94 символа в строке — обе вещи не видны на глаз в редакторе и ловятся только числом.

Проверки сайта и кадров требуют headless-браузера (Edge или Chrome) — на машине без него они не запустятся; остальные скрипты работают на одном Node.

`verify-ui-shots.cjs` открывает **собранный** интерфейс из `out/renderer/`, поэтому перед ним нужен `npm run build`: на пустом `out/` он честно сообщит «no frozen frame on the canvas», «0 resize handles» и ещё полтора десятка таких же ошибок, хотя с кадрами всё в порядке. `make-ui-shots.cjs` собирает страницу сам и предварительной сборки не требует.

### Проверка документации

```bash
npm run verify:docs    # node scripts/verify-docs.cjs
```

Проверяет то, что на GitHub ломается молча: каждая относительная ссылка в README, CHANGELOG, CONTRIBUTING и `docs/` ведёт на существующий файл, каждый якорь вида `#сборка-и-упаковка` указывает на существующий заголовок, каждый документ доступен по ссылке из README, а версия из `package.json` упомянута в README и в CHANGELOG. Разделение одного README на несколько файлов как раз и создаёт риск, что якорь останется в старом документе, — поэтому проверка появилась вместе с разделением.
