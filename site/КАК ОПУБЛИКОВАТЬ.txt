FLUSHOT — КАК ОПУБЛИКОВАТЬ САЙТ
================================

Эта папка — готовый статический сайт. Внутри нет ни базы данных, ни сборки,
ни зависимостей: index.html, стили, скрипт и картинки. Его можно открыть
двойным кликом прямо сейчас, и он полностью самодостаточен: ни один файл не
подгружается с чужого сервера.

Кнопки скачивания ведут не в эту папку, а в GitHub Releases
(https://github.com/aeshtlv/Flushot/releases/latest/download/...). Так сделано
намеренно: три архива весят 388 МБ, в репозиторий они не входят, а страница
с нерабочими кнопками хуже, чем страница без архивов.

Боевой адрес — https://flushot.ink. Он обслуживается nginx на своём сервере
(Алмалинукс 8, IP 78.17.32.87); папка выкладывается скриптом из репозитория.
Копия на GitHub Pages остаётся как резервная.


1. Посмотреть локально
----------------------

Самый простой способ: откройте index.html двойным кликом. Всё работает —
картинки, темы, меню на телефоне, кнопки скачивания (для них нужен интернет).

Есть один нюанс: по протоколу file:// некоторые браузеры ведут себя строже.
Если что-то покажется странным, запустите настоящий сервер:

    node scripts/serve-site.cjs

Он напишет адрес вида http://127.0.0.1:8080 и адрес для телефона в той же
сети — удобно проверить, как сайт выглядит на реальном экране.


2. Выложить в интернет
----------------------

Основной адрес — https://flushot.ink на своём сервере. Заливать нужно всю папку
site целиком, ничего дополнительно копировать не надо.

Вариант А. Свой сервер — так работает боевой сайт
  На сервере лежит /root/deploy-site.sh: он берёт папку site из ветки main
  репозитория и выкладывает её в /var/www/flushot.ink.

      ssh root@<ip-сервера>
      bash /root/deploy-site.sh

  Файлы раскладываются в /var/www/releases/flushot.ink-<дата>, а
  /var/www/flushot.ink — символическая ссылка на текущий выпуск. Ссылка
  переключается одной операцией, поэтому сайт не бывает наполовину залитым, а
  три предыдущих выпуска остаются на диске для отката. Подробности —
  в docs/HOSTING.md.

Вариант Б. GitHub Pages — тоже работает
  .github/workflows/pages.yml публикует эту папку при каждом изменении в main:

      https://aeshtlv.github.io/Flushot/

  Адрес в canonical указывает на flushot.ink, поэтому поисковики считают
  основной версией свой домен, а не эту копию.

Вариант В. Netlify Drop — без регистрации и без сервера
  1. Откройте https://app.netlify.com/drop
  2. Перетащите туда папку site
  3. Получите адрес вида https://имя.netlify.app — он уже работает

Вариант Г. Vercel, Cloudflare Pages — то же самое, через подключение
  репозитория. Для них папка site — это готовый «output directory», сборка не
  нужна.


3. Адреса в начале страницы
---------------------------

В index.html, в самом начале, три адреса прописаны на боевой домен:

  <link rel="canonical" href="https://flushot.ink/">
  <meta property="og:url" content="https://flushot.ink/">
  <meta property="og:image" content="https://flushot.ink/og-image.png">
  (и twitter:image — такой же)

Менять их нужно только при переезде на другой домен: подставьте свой адрес во все
четыре места. Там же лежит sitemap.xml — в нём один адрес, его тоже надо
поправить.

Почему это важно: превью ссылки в Telegram, VK и X требует АБСОЛЮТНЫЙ адрес
картинки. С относительным ссылка откроется, но без картинки.


4. Откуда берутся архивы для скачивания
---------------------------------------

Из GitHub Releases, а не из этой папки. Порядок такой:

  1. собрать программу:  npm run dist
  2. разложить архивы:   share/Flushot-<версия>-win64.zip и два других
  3. создать релиз с тегом v<версия> и прикрепить к нему эти три файла

Подробно — в docs/GITHUB.md в корне проекта. Ссылки на странице указывают на
releases/latest/download/<имя файла>, то есть на последний релиз: при выпуске
новой версии их менять не нужно, но имя файла должно совпадать с тем, что
прикреплено к релизу.

Проверить, что страница ссылается на существующий релиз, можно скриптом
(см. раздел 6) — он сверяет имена файлов с папкой share и версию с
package.json.


5. Как пересобрать картинки
---------------------------

    node scripts/build-site.cjs

Скрипт заново готовит оптимизированные картинки (WebP + PNG), иконки и превью
для соцсетей из docs/ и smm/. Архивы он не копирует — они живут в Releases.

Шрифты (Inter, JetBrains Mono) лежат не отдельными файлами, а прямо внутри
fonts.css в виде data:-URL. Это не оптимизация: браузер запрещает загружать
шрифт по file:// как кросс-доменный запрос, поэтому при открытии страницы
двойным кликом подключённый файл молча не применяется и текст рисуется
системным шрифтом. Если меняете шрифты — пересоберите:

    node scripts/build-fonts.cjs


6. Проверка перед публикацией
-----------------------------

    node scripts/verify-site.cjs

Проверяет: все ссылки ведут на существующие файлы, кнопки скачивания указывают
на этот репозиторий и на существующие имена архивов, у картинок правильные
размеры и alt-текст, контраст текста не ниже нормы WCAG AA в обеих темах,
нет дубликатов id и незакрытых тегов, нет внешних шрифтов и трекеров,
превью для соцсетей ровно 1200×630, шрифты вшиты в CSS и покрывают
кириллицу.

    node scripts/shot-site.cjs

Открывает сайт в headless-браузере на шести ширинах экрана и проверяет, что
нет горизонтальной прокрутки, ничего не обрезано, меню на телефоне
открывается и закрывается, а контраст в отрисованном виде соответствует
норме. Скриншоты складывает в .tmp/site-shots — их полезно просмотреть
глазами перед публикацией.


7. Что есть на сайте
--------------------

  index.html          главная страница
  404.html            страница «не найдено»
  styles.css          все стили, обе темы
  app.js              переключение темы, меню, вкладки скриншотов
  site.webmanifest    иконки и название для «Добавить на главный экран»
  robots.txt          правила для поисковиков, ссылка на карту сайта
  sitemap.xml         карта сайта, один адрес
  favicon.svg         иконка
  favicon-32.png      иконка для старых браузеров
  apple-touch-icon.png иконка для iOS
  icon-512.png        крупная иконка
  og-image.png        превью ссылки 1200×630
  assets/             картинки страницы, каждая в WebP и PNG


8. Чего на сайте нет
--------------------

Честно, чтобы не искать:

  — Архивов с программой: они в GitHub Releases (см. раздел 4).
  — Форм обратной связи и подписки: для них нужен сервер.
  — Аналитики: никаких счётчиков и трекеров, поэтому и статистики не будет.
    Если нужна — вставьте код счётчика сами перед </body>.
  — Английской версии.
  — Автоматической сборки: это статические файлы, собирать нечего.
  — Домена: его нужно получить отдельно, и тогда обновить адреса из раздела 3.
