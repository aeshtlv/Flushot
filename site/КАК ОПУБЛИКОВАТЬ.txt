FLUSHOT — КАК ОПУБЛИКОВАТЬ САЙТ
================================

Эта папка — готовый статический сайт. Внутри нет ни базы данных, ни сборки,
ни зависимостей: index.html, стили, скрипт и картинки. Его можно открыть
двойным кликом прямо сейчас.

Одно исключение: папка downloads пуста. Архивы весят 388 МБ, поэтому в
репозиторий они не входят, а лежат в share/ и в GitHub Releases. Перед
публикацией сайта их надо либо скопировать туда командой

    node scripts/build-site.cjs

либо оставить ссылки внешними — тогда ничего копировать не нужно, см. раздел 3.


1. Посмотреть локально
----------------------

Самый простой способ: откройте index.html двойным кликом. Всё работает —
картинки, темы, меню на телефоне. Кнопки скачивания без архивов, разумеется,
скачать ничего не смогут.

Есть один нюанс: по протоколу file:// некоторые браузеры ведут себя строже.
Если что-то покажется странным, запустите настоящий сервер:

    node scripts/serve-site.cjs

Он напишет адрес вида http://127.0.0.1:8080 и адрес для телефона в той же
сети — удобно проверить, как сайт выглядит на реальном экране.


2. Выложить в интернет
----------------------

Заливать нужно всю папку site целиком. Если архивы скопированы в downloads,
то вместе с ними; если ссылки ведут на GitHub Releases — без них. Три
бесплатных варианта, от простого к гибкому.

Вариант А. Netlify Drop — самый быстрый, без регистрации
  1. Откройте https://app.netlify.com/drop
  2. Перетащите туда папку site
  3. Получите адрес вида https://имя.netlify.app — он уже работает

  Минус: архив 383 МБ может не пройти — у бесплатного тарифа есть лимит на
  размер загрузки. Если не пройдёт, см. раздел 4.

Вариант Б. GitHub Pages — бесплатно и без лимита на размер файла
  1. Создайте репозиторий, залейте туда содержимое папки site
     (не саму папку, а то, что внутри: index.html должен лежать в корне)
  2. Settings → Pages → Source: Deploy from a branch → main → / (root)
  3. Через минуту сайт будет на https://<логин>.github.io/<репозиторий>/

  Важно: GitHub не отдаёт файлы больше 100 МБ через обычный git. Архивы по
  113–157 МБ туда не зальются. Тогда архивы надо положить отдельно —
  например, в Releases того же репозитория, и поправить ссылки в index.html
  на эти адреса (см. раздел 3).

Вариант В. Свой хостинг по FTP
  Залейте папку site в корень сайта (обычно public_html). Всё.

Вариант Г. Vercel, Cloudflare Pages — то же самое, что Netlify, через
  подключение репозитория. Для них папка site — это готовый «output directory»,
  сборка не нужна.


3. Что поменять после получения адреса
--------------------------------------

В файле index.html, в самом начале:

  <link rel="canonical" href="https://example.com/">
      → ваш адрес страницы

  <meta property="og:image" content="og-image.png">
      → полный адрес: https://ваш-домен/og-image.png

  <meta property="og:url" content="...">
      → добавьте эту строку с полным адресом

Почему это важно: превью ссылки в Telegram, VK и X требует АБСОЛЮТНЫЙ адрес
картинки. С относительным ссылка откроется, но без картинки.

Если архивы лежат не рядом с сайтом, поправьте три ссылки вида
  href="downloads/Flushot-2.2.8-win64.zip"
на реальные адреса. Их легко найти поиском по слову "downloads".
Про GitHub Releases — отдельная инструкция: docs/GITHUB.md в корне проекта.

Ещё: в robots.txt уберите комментарий и добавьте строку
  Sitemap: https://ваш-домен/sitemap.xml
когда появится домен.


4. Если архивы не проходят по размеру
-------------------------------------

Три ZIP-архива весят 388 МБ вместе (161 + 113 + 113). Если хостинг их не
принимает:

  — оставьте на сайте только Flushot-2.2.8-win64.zip (161 МБ);
  — или положите архивы на файлообменник и замените href на внешние ссылки;
  — или соберите установщик без ZIP: отдавать напрямую .exe (113 МБ), тогда
    браузер будет скачивать файл, а не архив. Для этого в index.html
    замените href на downloads/Flushot-2.2.8-x64.exe и положите в downloads
    сам exe вместо zip.

Проверить, что ссылки живые, можно скриптом:

    node scripts/verify-site.cjs

Он проверяет, что каждый файл, на который ссылается страница, существует.
Если архивов рядом с сайтом нет (например, они в GitHub Releases), запускайте
с ключом --no-archives: тогда всё остальное проверяется, а архивы пропускаются:

    node scripts/verify-site.cjs --no-archives


5. Как пересобрать картинки и скачанные файлы
---------------------------------------------

    node scripts/build-site.cjs

Скрипт заново готовит оптимизированные картинки (WebP + PNG), иконки,
превью для соцсетей и копирует свежие архивы из папки share. Запускать его
нужно после того, как вы пересобрали саму программу и в share появились
новые версии.

Если архивы пока не нужны (например, вы меняете только текст):

    node scripts/build-site.cjs --skip-downloads

Шрифты (Inter, JetBrains Mono) лежат не отдельными файлами, а прямо внутри
fonts.css в виде data:-URL. Это не оптимизация: браузер запрещает загружать
шрифт по file:// как кросс-доменный запрос, поэтому при открытии страницы
двойным кликом подключённый файл молча не применяется и текст рисуется
системным шрифтом. Если меняете шрифты — пересоберите:

    node scripts/build-fonts.cjs


6. Проверка перед публикацией
-----------------------------

    node scripts/verify-site.cjs

Проверяет: все ссылки ведут на существующие файлы, у картинок правильные
размеры и alt-текст, контраст текста не ниже нормы WCAG AA в обеих темах,
нет дубликатов id и незакрытых тегов, нет внешних шрифтов и трекеров,
превью для соцсетей ровно 1200×630, шрифты вшиты в CSS и покрывают
кириллицу.

    node scripts/shot-site.cjs

Открывает сайт в headless-браузере на шести ширинах экрана и проверяет, что
нет горизонтальной прокрутки, ничего не обрезано, меню на телефоне
открывается и закрывается, а контраст в отрисованном виде соответствует
норме. Скриншоты складывает в .tmp/site-shots — их полезно просмотреть
глазами перед публикацией.


7. Что есть на сайте
--------------------

  index.html          главная страница
  404.html            страница «не найдено»
  styles.css          все стили, обе темы
  app.js              переключение темы, меню, вкладки скриншотов
  site.webmanifest    иконки и название для «Добавить на главный экран»
  robots.txt          правила для поисковиков
  favicon.svg         иконка
  favicon-32.png      иконка для старых браузеров
  apple-touch-icon.png иконка для iOS
  icon-512.png        крупная иконка
  og-image.png        превью ссылки 1200×630
  assets/             картинки страницы, каждая в WebP и PNG
  downloads/          три архива с программой


8. Чего на сайте нет
--------------------

Честно, чтобы не искать:

  — Формы обратной связи и подписки: для них нужен сервер.
  — Аналитики: никаких счётчиков и трекеров, поэтому и статистики не будет.
    Если нужна — вставьте код счётчика сами перед </body>.
  — Английской версии.
  — Автоматической сборки: это статические файлы, собирать нечего.
  — Домена: его нужно получить отдельно, и тогда обновить адреса из раздела 3.
